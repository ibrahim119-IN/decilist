# Proof-first historical review protocol — 28 October 2026

This comparison evaluates actual time-to-verified-repair for a local model, not human developer productivity. It uses six newly selected historical bugs from p-map, p-timeout, p-some and delay, none used in the previous Decilist model trials. Their exact parent/fix commits, source bytes, dependency locks, licenses, public API descriptions and private probes are pinned before any participant inference. Public training contamination cannot be excluded.

Each parent and fixed revision has surrounding regression checks which must pass, plus a separate protected historical-target check which must fail the parent and pass the fix: 24 preparation outcomes. Ordinary input/error/cancellation/boundary behaviors are covered before evaluating proposed edits. These are bounded adapted probes, not complete upstream suites. No bug is injected. Corrected files are target controls, not universal clean labels; another real defect is possible. Six cases from four related library projects are not independent populations.

The same Qwen3-Coder-30B-A3B Q4_K_M runtime, full selected source, neutral API documentation, recommended JS ESLint diagnostics, strict structured output, generation limits, seed, local execution host and edit constraints are used in three arms:

1. `ordinary`: a test-capable reviewer proposes a hypothesis/test then a small isolated patch. It runs existing checks before editing and its proposed test plus existing checks after editing, without requiring its proposed test to fail on original source first.
2. `proof`: the new Decilist engine additionally requires a real tracked assertion failure on original source before requesting any patch. Syntax/import errors, timeouts, fabricated AssertionError and tests that already pass do not establish the defect. The exact same reproduction remains unchanged after the edit.
3. `proof_d1`: the same proof-first engine also receives one live pass of the existing d1 review specialist, unchanged default rules and 0.9 threshold. Advisory no-flags/unavailability is never approval.

This separates the verification workflow's value from the classifier's value. The ordinary baseline also receives line-range edits, fresh isolation and regression checks, so it benefits from general transport/hygiene improvements over the old prototype. It is not a human comparison or a full repository coding agent. Do not attribute all improvements to d1.

Every hypothesis is grounded in an exact source excerpt and claimed behavior. At most two hypotheses are generated in the initial call; each gets one patch proposal, at most two non-overlapping edits and 30 changed lines within the cited file/range. Every attempt starts from the same original snapshot. No earlier candidate is retained as the next attempt's base. SHA-256 guards stale edits. No tests, configuration or dependencies may be edited. Added capability filtering and bounded subprocesses are defense in depth, not an OS security sandbox. Existing packages are trusted open source; no network is used by probes.

The 180-second task clock includes live classifier assistance (when assigned), model calls, copying/materialization, baseline checks, reproduction, patch validation and final protected-target verification. Read-only corpus/lint preparation and model startup/download are outside both clocks. A failed or unaccepted target repair receives the full 180-second penalty in the primary time statistic; actual elapsed time is also retained. No success-only median. All attempts, rejected hypotheses, raw claims, requests/responses and test evidence are retained. A returned candidate is not yet a measured successful target repair: the independent protected target must pass and collateral behavior must remain intact.

Arm order rotates by case; order reverses on corrected controls (36 assignments). Requests are stateless with fixed seed, temperature 0 and prompt caching disabled, one observation per assignment. The provider sees neither case identifiers/variant labels, oracle tests, fix titles/patches/SHAs, reference fix source when reviewing the parent, nor other-arm responses. The evaluator does see references. The current model never reviews these cases before the freeze; a neutral unrelated example may test runtime/protocol compatibility. Failures during preparation are retained and resolved before exposure. No replacement after observing outcomes.

Freeze hashes of engine, adapter, CLI, harness, prompts, Node host, protocol, catalog, source/dependency manifests, lint, protected probes and runtime before the first case inference. A change afterward is an operational replay, not an untouched test. Post-trial claim adjudication is by the primary evaluator, not independent/blinded. Distinguish: verified target repairs; valid additional defects; confirmed false runtime claims; style-only noise; unproven hypotheses; infrastructure failures. An assertion proves a behavioral observation relative to its expectation, not by itself that the public contract is correct. Review the contract and accepted diffs before counting success.

Predeclared engineering gate for each proof arm versus ordinary: at least 3/6 accepted protected target repairs; no lower target-repair success; at least 20% lower failure-penalized median; at least half of all pairs faster on that same metric; and fewer confirmed false surfaced runtime allegations on corrected controls (if ordinary is zero, require zero). Unresolved accepted control findings prevent a clean false-positive claim. Rejected raw hypotheses are reported separately so silence cannot masquerade as improved diagnosis. No claim of human time saving is allowed; a separate real developer study is needed.

All artifacts remain on L. The previous eight JS defects and prior HTTPX fixtures may be development regression tests but are never part of this new cohort. The developer-facing deliverable is an optional `decilist review investigate` path which leaves original source intact and returns evidence and a reviewable candidate patch, not automatic application.
