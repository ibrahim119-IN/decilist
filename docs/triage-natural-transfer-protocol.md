# Historical upstream defect transfer check

This protocol is written before the root or assistant authors inspect the sealed historical defect mechanisms, tests or fixes, and before any assistant inference on them. It complements the separately frozen V6 model/context matrix; it does not replace or retrospectively change that experiment.

The author located four naturally occurring upstream defects with primary issue/commit evidence, pinned broken and fixed revisions, licenses and executable observations. A separate corpus-author comparison against all 73 V2–V6 catalog entries found no exact duplicates but one conservative semantic-family overlap. The strict transfer set is therefore **NAT-01, NAT-03 and NAT-04**. NAT-02 remains retained as an overlap control and receives no fresh-transfer credit. This exclusion precedes model outcomes. No claim of novelty relative to model pretraining is made: public historical fixes may have been seen during training.

Before use, the lab must retain actual broken-revision failures and fixed-revision passes with identical protected test/harness bytes and collection, separate passing invariants, all failed setup/reproduction attempts and original source/license hashes. Upstream production code must remain the actual historical code, without fabricated mutations. Any adapted test observation, dependency pin or environment accommodation must be described explicitly. The original four candidates have 111 checks, with 105 in the strict three-case set. Before any case exposure or model call, root independently reran the six strict broken/fixed variants with the actual frozen worker: broken versions produced 4 failures and 101 protected passes; fixed versions passed all 105. All 232 original source/test/license identities and 120 strict fixture files matched. This validates the test fixtures, not the assistant.

The main interpreter initially lacked `sniffio`. The bridge copies the licensed pure-Python `sniffio==1.3.1` into the worker's existing `vendor` root; main installed distributions and the frozen worker remain unchanged. Fixture inventories require exact ordinary-file maps, reject links/reparse paths and check both the source and created copy. The pre-exposure fixture identity is `dc484a64598a891435e1ef0a500d60553da91ade3b143f2f0a28011bfd688222`; bridge source SHA256 is `c0eeeab2ef447cb11bdbbd58bdbf96c945f8b7bf86d0cb72d74844d206d2d07e`. Raw case details and reference fixes remain evaluator-only until candidate freeze.

Keep reference fixes, upstream issue/commit descriptions, evaluator registry, later source and prior attempt outputs outside participant trees. Participants receive a neutral task, broad production roots, the actual broken project, protected test selectors and the same ordinary development tools. The later reference implementation is evaluator evidence, not model context or a participant repair oracle. The model sees only context collected by the frozen assistant from the broken project and actual test failure.

Use the preselected local Qwen3.6-27B Q8_0 non-thinking profile and V6 context design. The candidate may be chosen or improved using already exposed development/V6 evidence, but its exact code, prompt, parameters, context budget, guard policy, runtime, native mode proof, measurement code and protocol must be frozen **before** the root or assistant authors inspect this strict transfer set. Any such prior development is reported; transfer results cannot be used to tune and then be relabeled fresh. Preserve the earlier V6 candidate and results. A different model or generation budget requires an explicit dated amendment before transfer exposure.

Do not run a separate assistant evaluation on these three defects before timing. Their first assistant calls occur inside the assigned assisted trials. This gives three first-call repair observations alongside three paired end-to-end time comparisons. Start the clock before inspecting failure/source/hint. Generic measurement API preparation may happen first, but no case information. Use the same minimal action ledger, unchanged protected tests and 900-second cap for both arms. Assisted agents make exactly one initial live workflow call inside the clock; its bounded internal retry, test verification, application and failed stages all count. A tested `--apply` repair can finish through protected validation in that call. Otherwise continue manually in the same arm, without another model/hint or subtracting failed-assistance time. Ordinary-tool agents cannot read previous trials or public reference fixes. Preserve every timeout, error, invalid record and failed repair.

Root reruns the protected checks outside the participant clock and inspects actual production diffs, canonical source hashes, unchanged tests/configuration/collection, execution coverage, hint provenance and assigned treatment. This records test-supported repairs, not exhaustive semantic correctness. Local records and instruction-based separation do not prove absence of unrecorded reads.

The prespecified engineering gate requires at least **2/3 initial assistant calls** to supply protected passing repairs, **3/3 final protected repairs in each arm**, at least **2/3 pairs faster** with assistance, and at least **20% lower descriptive median total elapsed time** for assisted slots. Report each paired difference, every assistant failure/manual continuation, and stage costs. Do not calculate a favorable median from successes alone while dropping unfinished cases. These small thresholds are a development gate, not statistical significance or a population estimate. Three paired historical defects are not six independent human tasks.

All files, models, caches, environments and temporary work remain on L. Projects are explicitly trusted and execute with caller OS permissions; copied trees and static guards are not a security sandbox. Tests use deterministic/local observations without external network requests. Downloads, model loading, one-time installation and switch costs are recorded separately from warm task latency; a warm repair-time result does not establish that initial setup has already paid for itself.

Publish the actual outcomes and limitations even if the gate fails. A positive agent result permits only a bounded claim about this measured engineering experiment. Human developer productivity, onboarding experience and general time savings remain unmeasured until actual consenting developers complete an appropriate study. No recruitment or fabricated human participation is authorized.
