# إصلاح اختبار موجود باستخدام Decilist V6

دي نسخة تجريبية لمشاريع Python الموثوق فيها. بتجمع السياق من الاختبار اللي فشل، وتقترح تعديل صغير، وتجربه في نسخة منفصلة مع اختبارات الرجوع الموجودة. مفيش فورم ولا تعريف قرار جديد لكل عطل. جودة الإصلاح وتوفير الوقت في V6 لسه تحت القياس؛ نتائج V5 السلبية محفوظة في [التقرير](triage-v5-results.md).

## تجهيز مرة واحدة

من نسخة المستودع، ثبّت الحزمة في بيئة تطوير مشروعك مع اعتمادياته واختباراته المعتادة:

```bash
python -m pip install -c requirements-dev.lock -e "./packages/python[dev]"
```

المساعد بيستخدم نفس Python اللي شغّلته؛ اعتماديات مشروعك لازم تكون متاحة فيه. الموديل وخادم `llama.cpp` لهم إعداد منفصل، والأمر ده ما بينزّلش أوزانًا. الإصدار الحالي متحقق منه مع البناء `b11889-d854d98ba` وسياق 16384 token.

على Windows مع CUDA، [أداة إعداد Qwen3-Coder الموجودة](stronger-local.md) بتنزّل الملف المحدد وتتحقق منه. للتشغيل مع V6 استخدم `--context 16384` صراحةً بدل القيمة الافتراضية القديمة:

```powershell
python scripts/setup_stronger_local.py download --cache-dir L:/DecilistModels/qwen-coder
python scripts/setup_stronger_local.py serve --cache-dir L:/DecilistModels/qwen-coder --gpu 0 --context 16384
```

التنزيل صريح وحجمه حوالي 18 جيجابايت. سيب نافذة الخدمة مفتوحة وافتح تيرمنال تاني للمساعد. دي تجربة على جهاز بكارت RTX 3090 وذاكرة 24 جيجابايت؛ مش وعد بالتوافق مع أي لابتوب. اتبع متطلبات أداة الإعداد ورخص الموديلات في الدليل المرتبط.

بعد تشغيل خادم Qwen3-Coder المحلي، احفظ إعداداته الفعلية بأمر واحد:

```bash
python -m decilist.triage_setup --profile qwen3_coder_non_reasoning --output decilist-model.json
```

الأمر بيتحقق من هوية الخادم وقالب الموديل ويحفظهم؛ ما بيولّدش إجابة، وما بيستبدلش ملف إعداد موجود. العنوان الافتراضي `http://127.0.0.1:8792`. لو اخترت Qwen3.6-27B، شغّله بوضع `--reasoning off` واستخدم `--profile qwen3_6_closed_thinking`. الخادم لازم يكون جاهز بالفعل؛ دعم القالب مش دليل إن الموديل أصلح العطل.

## وقت فشل اختبار

من التيرمنال اللي بتشتغل منه بالفعل:

```bash
python -m decilist.triage_v6 --project . --test tests/test_checkout.py --regression tests/test_cart.py --work-dir ../debug-run-01 --model-config decilist-model.json --capture-failure-text --apply
```

بدّل أسماء الاختبارات باختبارات مشروعك الحالية. اختار مجلد عمل جديد خارج المشروع لكل محاولة. `--apply` بيطبّق التعديل فقط بعد نجاح الاختبارات المحمية ومراجعة إن ملفاتك ما اتغيرتش أثناء التجربة. احذفه لو عايز تشوف التعديل والنتيجة الأول. `--capture-failure-text` بيسمح بإدخال تفاصيل فشل الاختبار للموديل المحلي؛ احذفه لو القيم حساسة.

لو كودك في مجلد غير `src` أو `packages/python/src` أو `vendor`، حدده باستخدام `--production-root اسم_المجلد`. للمشروع اللي ملفاته مباشرة في الجذر استخدم `--production-root .`. اختار اختبارات رجوع تحمي السلوك المرتبط بالعطل؛ نجاح اختبار واحد مش ضمان لصحة المشروع كله.

النتيجة بتعرض الفرضية والـdiff ونتائج الاختبارات. `hypothesis_supported_by_tests` معناها إن التعديل عدى الاختبارات المحددة. `unverified` أو `needs_review` معناها إن مفيش إصلاح مثبت؛ تقدر تكمل بأدواتك المعتادة من نفس مكان الشغل. الرد المتوقف أو غير الصالح ما بيتحوّلش لتعديل في مشروعك. راجع الـdiff وشغّل اختبارات المشروع الأوسع قبل الدمج.

## من أداة التطوير بتاعتك

```python
from decilist.triage_v6 import run_triage_v6, format_text

report = await run_triage_v6(
    project=project_path,
    tests=["tests/test_checkout.py"],
    regressions=["tests/test_cart.py"],
    work_dir=new_work_directory,
    model_config=model_config_path,
    capture_failure_text=True,
    apply=True,
)
print(format_text(report))
```

تقدر تحط الاستدعاء بعد أمر الاختبارات الموجود في أداة التطوير. المساعد بيستخدم الاختبارات والكود، مش بيانات Playground. تجميع السياق بيفرق بين الدوال اللي اتنفذت، وروابط الحالة المستنتجة من الكود، والدوال المساعدة اللي اتقرت فقط. الفلتر بيرفض تعديل الاختبارات، والردود اللي بتكرر نفس الكود، والتعديلات الخارجة عن النطاق المسموح.

على جهاز العرض، استخدم النسخة الفعلية على `L:\CodexData\Decilist\outputs\decilist` وخلي مجلد العمل والملفات المؤقتة على L. الاختبارات بتتنفذ بصلاحيات المستخدم العادية، والنسخة المنفصلة مش بيئة عزل أمني.

[بروتوكول المقارنة](triage-v6-experiment.md) بيفصل أثر الموديل عن أثر تجميع السياق. وقت انتظار الموديل وجمع السياق والتحقق وأي استمرار يدوي بيتحسب ضمن التجربة. تجارب الوكلاء مش قياسًا لوقت مطور بشري.
