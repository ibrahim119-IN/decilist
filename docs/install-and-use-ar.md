# إضافة Decilist لمشروع موجود

Decilist مكتبة Python محلية وواجهة قرارات عامة. مساعد فشل الاختبارات طبقة اختيارية فوقها: بياخد سجل فشل محفوظ، ويعرض حقائق من السجل والكود وخطوة فحص مقترحة. مش محتاج حساب أو Playground أو تسجيل قرارات مسبقًا.

الحزمة حاليًا alpha، وبتتثبت من checkout أو wheel مبني من المشروع. **لسه مفيش إصدار منشور على PyPI أو npm.** نجاح التثبيت مش دليل على دقة الموديل أو توفير وقت التصحيح؛ [النتائج المقاسة وحدودها](triage-results.md) منفصلة عن خطوات الاستخدام.

## 1. ثبّت المكتبة مرة واحدة

مطلوب Python 3.11 أو أحدث. من مجلد Decilist، وفي بيئة Python اللي مشروعك بيستخدمها:

```powershell
python -m pip install ./packages/python
```

لو معاك wheel مبني محليًا، استخدم مساره بدل مجلد المصدر:

```powershell
python -m pip install ./decilist-0.1.0a1-py3-none-any.whl
```

الإصدار والمسار في الأمر لازم يطابقوا الملف اللي معاك. الحزمة الأساسية بتثبت SDK واعتمادياته الخفيفة؛ مش بتثبت PyTorch أو CUDA أو بتنزل موديل. لو عندك runtime شغال في بيئة موديل منفصلة، تطبيقك محتاج الحزمة الأساسية بس. ماتعيدش تثبيت اعتماديات GPU داخل كل مشروع.

## 2. شغّل المساعد على سجل فشل موجود

من مجلد مشروعك، بعد حفظ نتيجة الاختبارات الفاشلة في `failed.log` بالطريقة المعتادة:

```powershell
decilist triage --log failed.log --project .
```

ولو الأمر `decilist` مش ظاهر في مسار الأوامر، نفس الوظيفة متاحة من مفسّر Python اللي ثبتّ فيه الحزمة:

```powershell
python -m decilist triage --log failed.log --project .
```

المساعد ما بيشغّلش اختبارات أو أوامر من السجل، وما بيعدلش المشروع. بيقرأ السجل ومقتطفات محدودة من الملفات المشار إليها داخل `--project`. تشغيله أو استيراد المكتبة ما بيبدأش runtime وما بينزلش موديل تلقائيًا.

الوضع الافتراضي `--mode auto`: لو فيه دليل مباشر تنطبق عليه قاعدة محددة، يطلع اقتراح من القواعد. غير كده يحاول استخدام موديل محلي متعلّم شغال بالفعل. استخدم `--mode rules` عشان تفحص بالقواعد فقط من غير runtime، أو `--mode model` عشان تطلب مسار الموديل صراحةً. وضع `demo` في runtime مثال بقواعد، وما بيتقدمش على إنه موديل متعلّم.

عشان تحفظ تقريرًا جديدًا يمكن قراءته من برنامجك:

```powershell
decilist triage --log failed.log --project . --format json --output triage-report.json
```

اختار اسم ملف جديد؛ المساعد بيرفض الكتابة فوق ملف موجود. إخفاء الأسرار آليًا تقريبي، فراجع السجل والتقرير قبل مشاركتهم.

## 3. أضفه لكودك في سطور قليلة

داخل دالة `async` في تطبيقك أو أداة CI المحلية:

```python
from pathlib import Path
from decilist.triage_assistant import diagnose
from decilist.triage_evidence import prepare_evidence

project = Path(".")
evidence = prepare_evidence(saved_failure_log, project=project)
report = await diagnose(evidence, project=project, mode="auto")
print(report["status"], report["source"], report["next_check"]["title"])
```

`saved_failure_log` هو نص السجل اللي تطبيقك جمعه بالفعل. المثال الكامل [triage_in_existing_app.py](../examples/triage_in_existing_app.py) بيقرأ ملفًا محفوظًا وبيطبع JSON. شغّله من checkout:

```powershell
python -m examples.triage_in_existing_app --log failed.log --project . --mode rules
```

لو عندك أكتر من طلب، تقدر تمرر `client` محليًا وتعيد استخدام اتصاله. إغلاق الـclient بيقفل الاتصال فقط؛ مش بيوقف runtime شغال.

## 4. إعداد الموديل اختياري ومنفصل

القواعد لا تحتاج موديل. لو هتستخدم Liquid، نفّذ الإعداد في بيئة الموديل مرة واحدة، وراجع [شروط الموديل والكود المثبت بإصدار محدد](providers.md). من مجلد Decilist، بعد تفعيل بيئة الموديل:

```powershell
python -m pip install "./packages/python[server,liquid]"
python -m decilist runtime setup liquid --allow-download --allow-model-code --device cuda
python -m decilist runtime start --provider liquid --allow-model-code --device cuda
```

أمر `setup` هو الخطوة الصريحة اللي بتحتاج إنترنت لتحميل ملفات الموديل، وبيستفيد من الملفات الموجودة في cache. بعد نجاح الإعداد، `start` بيحمّل من الـcache فقط ويمكن تشغيله بدون إنترنت. لو الملفات ناقصة، هيوضح الفشل من غير تنزيل تلقائي أو تغيير المزوّد. اعتماديات Python نفسها لازم تكون مثبتة قبل التشغيل بدون إنترنت. `--device cpu` بديل صريح لو مفيش CUDA مناسب، والأداء حسب الجهاز.

سيب نافذة runtime مفتوحة واستخدم المساعد من تطبيقك أو نافذة تانية. العنوان الافتراضي `http://127.0.0.1:8765`. لو بتستخدم منفذًا محليًا مختلفًا، اضبط `DECILIST_URL` في بيئة التطبيق. المساعد بيرفض إرسال الأدلة إلى عنوان بعيد. راجع [تشغيل runtime ودمج SDK](runtime.md) للأوامر الكاملة.

## قراءة النتيجة

| الحقل | معناه |
| --- | --- |
| `facts` | تفاصيل مستخرجة من الأدلة المتاحة؛ وجودها مش إثبات لسبب جذري |
| `next_check` | عنوان وخطوات فحص مقترحة؛ مش إصلاح تم تنفيذه |
| `status: suggested` | فيه اقتراح اجتاز شروط المسار المستخدم |
| `status: needs_review` | الأدلة أو قرار الموديل محتاجين مراجعة؛ ما تعتمدش على اقتراح غير مقبول |
| `status: unavailable` | مسار الموديل غير متاح أو الطلب فشل؛ الحقائق المتاحة تفضل ظاهرة |
| `source: rules` | قاعدة محلية معلنة؛ مفيش ثقة AI منسوبة للقاعدة |
| `source: model` | الموديل شارك في النتيجة؛ راجع القرار والسياسة وبيانات المزوّد |
| `source: none` | مفيش اقتراح مقبول من القواعد أو الموديل |

قبول اقتراح الموديل محتاج ثقة لا تقل عن `0.7` مع اجتياز عقد القرار. الثقة احتمال مسار عند الموديل، مش احتمال إن التشخيص أو الإصلاح صحيح. التقرير بيحتفظ بمصدر النتيجة والسياسة وبيانات القرار المتاحة عشان تقدر تراجعها. حقائق السجل ومقترحات الفحص أو أي ترشيحات غير مؤكدة مش بديل عن اختبار الإصلاح.

كود خروج CLI هو `0` عند `suggested`، و`1` عند `needs_review` أو `unavailable`، و`2` لخطأ في المدخلات أو الملفات. ده كود المساعد، مش كود الاختبارات الأصلية؛ احتفظ بنتيجة اختبارك بشكل منفصل وما تعتبرش نجاح المساعد نجاحًا للـCI.

## التحقق الفعلي من التثبيت

نسخة wheel الحالية اتثبتت واتجربت آليًا بواسطة وكيل في بيئة Python جديدة خارج checkout على Windows. نجح أمر `decilist triage`، والـAPI القصير، والمثال الكامل، وإعادة استخدام runtime الموجود من غير إعادة تشغيله. بيئة التطبيق ما اتثبتش فيها PyTorch أو Transformers أو اعتماديات الخادم. استغرق تثبيت SDK واعتمادياته `6.26` ثانية في ظروف الشبكة والـcache الموجودة وقت الاختبار؛ إنشاء البيئة وبناء الحزمة متسجلين بشكل منفصل.

طلب الموديل الفعلي رجّع `needs_review` بسبب ثقة أقل من العتبة، مع الاحتفاظ بالحقائق ومحاولة Liquid في سجل القرار. اختبار عنوان محلي غير متاح رجّع `unavailable` صراحةً. دي أدلة تشغيل وتثبيت بواسطة وكيل، مش قياسًا لسهولة الاستخدام عند مطوّر بشري أو لتوفير وقت التصحيح.
